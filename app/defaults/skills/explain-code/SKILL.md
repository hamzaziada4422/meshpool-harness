# Explain code

1. Read the README and the entry points first, then follow the call path for the question. Do not read every file.
2. Answer in this order: what it does in two sentences, a map of the folders that matter, the path a request or action takes, where to change what they asked about.
3. Quote file paths with line numbers. Say what you did not check.

Rules: Write in plain sentences, no em dashes. Save results in the project's "Meshpool outputs" folder unless the user names a place. Look at every visual result with view_output (or ui_audit for web pages) before you say it is done. Reply with the file path and two sentences on what it is.
