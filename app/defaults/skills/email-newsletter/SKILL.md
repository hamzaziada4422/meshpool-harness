# Email newsletter

Do the asked thing first: write the newsletter now from what the user gave you. One deliverable, one file. No plan document, no tracker, no research unless the user asked for facts you do not have.

1. One column, 600 px wide, tables for layout, inline styles, system fonts, a real text link for every button, alt text on images.
2. One message and one button. Subject under 50 characters. Use [placeholders] for facts you do not have (address, prices, dates) and list them in your reply.
3. Save one .html file. Look at it once with view_output at 600 px, fix only what is broken, and draft only: never send. No separate plain-text file unless asked.

Rules: Write in plain sentences, no em dashes. Save results in the project's "Meshpool outputs" folder unless the user names a place. Do not ask questions you can answer with a sensible choice. Reply with the file path and two sentences on what it is.
