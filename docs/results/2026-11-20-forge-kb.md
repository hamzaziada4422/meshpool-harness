## A. Calibration from the reference decks

62 more, 66 in all) that count only as written or with -s, never as -ed or -ing forms (those are mostly adjectives in topic
labels). No numeric threshold changed: the 130 reference decks do not clearly dispute any (baseline file, "Thresholds
the reference decks dispute").

Evidence: on the dev briefs, all 6 P11 failures were sentences with a verb the lexicon missed. On 4,138 English
reference titles the verb share moves from 59.8% to 60.5%. A sample of 33 newly passing reference titles was read:
the ones still wrong came from words that double as nouns ("phases", "guide", "release"), which were then removed.
A unit test pins both sides (sentences pass, topic labels such as "Three priorities for the fourth quarter" and
"Operating division trends" fail).

Considered, not changed:

  chart provenance in `provenance.json`, and the reference data does not show it is safe.

## Live builds (DeepSeek V4.1 Flash, Meshpool endpoint, 2026-11-20)

Four short random briefs, built end to end (storyline, content, render, validators, up to 4 repair rounds), band
frame with a style pack each. Reviewers off (default). Model spend is not visible to the test key; call counts are.

| Brief | Slides asked / built | Style | Rules failing at the end | Repair rounds (content failures) | Model calls |
|---|---|---|---|---|---|

| b2 cloud contract decision | 3 / 3 | navy-corporate | none (P19 not run on 3 slides) | 4, 5, 3, 2, 4, best round 3 kept | 19 |
| b3 payments market entry | 3 / 3 | teal-modern | P10 | 9, 5, 3, 4, 4, best round 2 kept | 17 |
| b4 nurse staffing plan | 6 / 6 | charcoal-orange | P10, P14, P20 | 26, 30, 22, 23, 18 | 37 |

Engine defects the live builds found, fixed with tests (`app/tests/test_forge_kb_rootcauses.py`):
1. The repair loop kept its last round even when it was worse (P10 and P11 passed in rounds 2-3 and failed again in
   round 4). The best round is now kept and drawn again; it was restored in 3 of 4 builds.
2. A "$M" chart turned into big figures read "$41.326%" (a category mentioned "2%") and "$41.2M" became "$41.2".
3. "No cover slide" added a cover ("cover slide" matched); negations now count. b1 was built before this fix.

4. A deck asked for 2 slides came out with 3: the planner always kept 3 narrative slides. The minimum is now 1.
5. The model planned a cover when the brief said "no cover". A planned cover is dropped unless the brief asks for one.

Reruns after the fixes, with the built-in layouts in the storyline prompt:

|---|---|---|---|---|

| b5 again, after the P14 message change | 3 / 3 | P13, P14 | 0 | 13 |
| b5 with point cards (headers written by the model, icons by meaning) | 3 / 3 | P10, P13, P14 | 3 | 17 |

The P14 failures left are figures from the brief quoted beside a chart that does not plot them (growth rates beside a
volume chart). The rule asks for every number in a chart slide's text to match the chart; the repair loop did not move
them off the chart slide. The repair message now says where such a figure goes (a footnote, a slide without a chart,
or out). One rerun of b5 still failed P14, and also P13 on figures the model derived (a 0.37 point gap) without a
fact: with this model, number discipline is the limit, not the renderer. Model spend is unknown: the
gateway does not expose it to the key (below).

The b5 rerun with point cards also found a table written with object cells and a half-empty column, drawn as a
numbered list of "N/A"s. Object cells keep their sources, and a column half or more N/A now goes (its few values
footnoted), so the slide stays a table.

Gateway check (2026-11-20): chat completions answer; `/v1/models` lists 17 models and matches what the gateway serves;
`/v1/usage` answers 401 for this key, so spend cannot be read from the session.

What is left is mostly the model's writing: repeated facts across a row's label and cells, and arithmetic slips (an
annual cost added to 18-month costs) that the tie check flags but the repair does not always fix.
