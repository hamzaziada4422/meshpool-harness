# ws18-browser: browser use and computer use

Base: `claude/sleepy-faraday-tkjcox`; branch `audit/ws16-18`. Paths are under `app/meshpool_harness/` unless they start
with `app/`. Tests: `app/tests/test_ws18_browser.py` (real Chromium, skipped when none launches) and
`app/tests/test_ws18_caps.py`. Each test was run with the fix reverted (source files only) and failed (10 of 10 in
`test_ws18_browser.py`), then passed.

| ID | Status | Root cause | Fix | Files | Test |
|---|---|---|---|---|---|
| M32-01 | fixed | A browser call whose client timed out (or pressed Stop) stayed in the browser thread's queue and ran later, on whatever page was current: a double click or double submit. | `Browser.run` takes a cancel flag from the call (`mcp_stdio.cancel_check`) and a skip flag set on timeout; the browser thread drops a skipped item. `mcp_stdio.serve(serial=True)` also drops a call cancelled while it waits for the lock. The client now sends `notifications/cancelled` on timeout and Stop (ws16). | agent/browser_mcp_server.py, agent/mcp_stdio.py | tests/test_ws18_browser.py::test_cancelled_queued_call_is_dropped, ::test_timed_out_queued_call_is_dropped, ::test_serve_does_not_start_a_cancelled_queued_call |
| M32-02 | fixed | Every chat started its own browser server on the same persistent profile; Chromium cannot share it and the second chat got a launch error that did not say why. | A per-profile OS lock (`ProfileLock`, released when the process dies): the second chat gets "The browser is in use by another chat (chat ...): ... wait, or call browser_close there". Not a shared browser process (that would need a broker; the message was the cheaper of the two options named). | agent/browser_mcp_server.py | tests/test_ws18_browser.py::test_second_user_of_the_profile_gets_a_clear_message, ::test_a_second_browser_server_on_the_profile_is_refused_with_that_message |
| M32-03 | fixed | `ctl start` answered "browser already running" to any reply from the daemon, even when its page or Chromium had died. | `_outdir` checks the browser is connected and replies with an error when it is not; `start` then stops the old daemon, removes its state file and starts a new one. A closed page is replaced inside the same context. | engines/browser/ctl.py | tests/test_ws18_browser.py::test_ctl_restarts_when_its_browser_died_and_does_not_say_already_running |
| M32-04 | fixed | The daemon kept the previous task's page, cookies and output folder; parallel tasks shared one page. | One browser context, page and state per task (`MH_TASK_ID`, default one task): `start <other folder>` gives a fresh context (no cookies) and its own folder; the same task starting again resets nothing; two task ids have separate pages. | engines/browser/ctl.py | tests/test_ws18_browser.py::test_ctl_new_task_gets_clean_cookies_page_and_folder, ::test_ctl_parallel_tasks_do_not_share_a_page |
| M32-05 | fixed | `target=_blank` / `window.open` tabs were followed only by `browser_click`'s own check; a popup from a key press, a script or a form left the agent on the old page. The ctl daemon never followed. | The browser context listens for pages opened by the current page and switches to them (with a one-line note; `browser_tabs` switches back). ctl does the same per task. | agent/browser_mcp_server.py, engines/browser/ctl.py | tests/test_ws18_browser.py::test_popup_from_a_script_is_followed, ::test_ctl_follows_a_new_tab |
| M32-06 | fixed | `STATE["scale"]` started at 1.0 and was set by the first screenshot only; a click before it landed at the wrong place on Retina/scaled screens. | The scale is computed from the screen size when first needed and at server start (`_scale()`), the same formula the screenshot uses. | agent/computer_mcp_server.py | tests/test_ws18_caps.py::test_click_before_any_screenshot_uses_the_screens_scale, ::test_small_screen_scale_is_one |
| F-27 | fixed | Capabilities showed Browser use as available whenever the server was in `mcp.json`, even without the Playwright package or with a chosen browser that is not installed. | `unavailable_reason()`: the row is unavailable, off, and carries the reason; turning it on is refused with the same text; the page shows the reason and disables the switch. | ui/settings_v2.py, ui/settings2.js | tests/test_ws18_caps.py::test_browser_use_without_playwright_is_not_offered, ::test_browser_use_with_a_missing_chosen_browser_says_so |
| F-37 | fixed | Capabilities offered Computer use on Linux (the page ignored `computer_status`, which already said unsupported). | Same mechanism: unsupported platforms are unavailable with the status summary; supported-but-not-ready stays switchable. | ui/settings_v2.py, ui/settings2.js | tests/test_ws18_caps.py::test_linux_does_not_offer_computer_use, ::test_supported_computer_use_stays_available, ::test_ui_shows_the_reason_and_disables_the_switch |
