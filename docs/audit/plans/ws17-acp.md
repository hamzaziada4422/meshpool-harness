# ws17-acp plan: outside harnesses (ACP, Pi, Hermes, Codex, OpenCode)

Checked against the audit base (370427e3). Every item below still reproduces there unless noted.
Tests go in `app/tests/test_ws17_acp.py` (fake ACP agent and fake Pi RPC binary, so the state machines run in CI)
and `app/tests/test_ws17_real_harness.py` (the real Pi and Codex binaries, skipped when not installed).

| ID | Root cause (file:line on the base) | Fix | Regression test |
|---|---|---|---|
| M23-01 | `harnesses/acp.py` `_request`: the Stop check only covers `session/*` methods, so `initialize` (300 s) and `authenticate` (120 s) wait out their timeouts; `stop()` sends nothing while there is no session. | `_request` gives up within 0.3 s on Stop for every method that is not `session/prompt` (no cancel can reach a harness that is starting); the half-started process is ended at once; `send` checks Stop again after start-up, before the prompt. | fake ACP whose `initialize` never answers: Stop ends the turn in < 3 s, reported as interrupted. |
| M23-03 | `acp.py` `send`: the `refusal` + `_reloaded` retry ignores `self._stop`. | Retry only when not stopped. | fake ACP answers a cancelled prompt on a reloaded session with `refusal`: no second `session/new`/prompt. |
| M23-05, M16-04 | `harnesses/__init__.py` `prepare_hermes/prepare_codex/prepare_opencode` rewrite one shared file per harness in place (`write_text` / `O_TRUNC`) with the chat's provider, model and key. Hermes re-reads config.yaml when its mtime changes. | Hermes: config.yaml no longer holds the provider: `${MESHPOOL_HERMES_*}` references, resolved by Hermes from each process's own environment (set per launch); the file is identical for every chat and written atomically only when it changes. Codex: a config folder per chat (`codex/chats/<id>`, `CODEX_HOME` set per process). OpenCode: a config file per chat (`OPENCODE_CONFIG`). All writes atomic (temp + replace), `write_private` included. | two chats on different models prepare concurrently: each process env/config names its own model; the shared Hermes file carries no model or key; no partial file is ever observed. |
| M24-03 | `harnesses/pi_rpc.py` `prepare`: one shared `<home>/pi` with mcp.json (project path, tokens), models.json, settings.json, rewritten per launch; skills synced into it with rmtree/copytree. | A Pi agent folder per chat (`pi/chats/<id>`: models, mcp, settings), written atomically; the shared skills folder is synced under a file lock and listed in each chat's settings (`skills`). | two Pi chats in different projects: each mcp.json names its own project. |
| M24-01 | `ui/agent_api.py` `send` calls `PiAgent.steer` under `Session.lock`; `steer` waits for Pi's reply, but Pi's reader thread is blocked in `emit` (which takes `Session.lock`) on an earlier event, so the reply is never read: 30 s freeze, `PiError`, the user event never shown. | `pi_rpc.py`: the reader only reads; command replies and queue updates are handled on it, all other events go through a dispatcher thread, so a reply is never stuck behind a blocked emit. | emit callback takes a lock the steering thread holds: steer returns in < 5 s and the added message is shown. |
| M24-02 | `pi_rpc.py` `_reader` sets `_done` at EOF, so `send` takes a crash for a finished turn. | EOF sets an `_exited` event (after every earlier event is dispatched), never `_done`; `send` reports the crash, restarts Pi on its own session (`--continue`) and asks it to carry on, once per turn; a second crash is an error. | fake Pi exits mid-reply: the turn shows the crash, restarts, continues, and the answer comes from the resumed run. |
| M24-04 | `pi_rpc.py` `steer` writes to `self._p` while Pi is still starting (`_p` None): AttributeError -> "Pi stopped". | Steers that arrive before Pi is up are held and handed to Pi (as steering) as soon as it runs; a steer Pi queued after its run ended is answered by `has_steers/resume_steers` (the Session already calls these). | steer during a slow start: no error; Pi receives it; it is shown once. |
| M25-01 | `agent/assistant_mcp_server.py run_subtasks` stops only on `notifications/cancelled`, which harnesses need not forward; Stop's process sweep leaves MCP servers alone. | Each chat's Meshpool MCP servers get `MESHPOOL_STOP_FILE`; ACP and Pi `stop()` stamp it; `run_subtasks` also stops when the stamp is newer than the call. | a sub-agent loop with no cancel notification stops within a second of the chat's Stop. |
| M36-01 | `agent/acp_server.py prompt`: each prompt runs on its own thread; `Agent.send` resets `_stop`, so the cancelled turn keeps running. | Prompts of a session run one at a time (a per-session lock); a prompt that was cancelled before it started answers `cancelled` at once; stopReason comes from the turn's own cancel state. | stub Agent: cancel then prompt: the first turn reports `cancelled` and never overlaps the second. |
| M03-02 | `ui/agent_api.py` turn epilogue: `elif self.queue: self.queue = []` drops messages queued after Stop (Stop itself already clears the earlier queue) without clearing the chip. | Messages still queued at the end of a stopped turn run next (with the ACP "previous request was stopped" note); the chip clears. | Session on the fake ACP harness: Stop, queue a message, it runs and the chip count returns to 0. |
| M14-02 | `acp.py mcp_servers_for_acp` passes connector URL + the current OAuth header to the harness; it never refreshes. | Connectors with credentials reach harnesses through a stdio bridge (`agent/connector_bridge.py`) that uses Meshpool's own MCP client, which refreshes the token on 401. | a fake HTTP MCP server that rejects the old token: the bridged call succeeds after refresh; the harness config carries no token. |
| M05-05 | `ui/agent_api.py revert` cuts the transcript only; the harness session keeps the undone turns. | `revert` calls `agent.forget_session()`: ACP drops its session (the next turn opens a new one with the cut history carried), Pi moves its session files aside and restarts with the cut history. | fake ACP: after Undo, the next prompt goes to a new session and carries only the kept turns. |
| D-03 | Only code-read in the audit. | Fake-binary tests above for both state machines, plus real Pi 0.73.1 / Codex 0.171.0 tests against the mock LLM where installed. | `test_ws17_real_harness.py`. |

Also: ACP `session/prompt` usage (when the harness sends it) is added to the turn's usage, so the ledger counts it.
