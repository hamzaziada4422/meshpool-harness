# Insight precision and recall (0.0.10)

Each family was run on 30 hand-labelled situations (`testkit/insights_precision.py`). A situation is a small made-up history and a label written from the product rules: would a person want this card (positive) or is it noise (negative). Precision is hits over hits plus false alarms; recall is hits over hits plus misses. A type with precision of 0.8 or better ships on by default; below that it ships off (`insights.DEFAULT_ON`).

**Tuning history.** The first run, before any detector change, scored connect 0.94, remember 0.94 and followup 0.84. The false alarms were Jira-style keys that were part numbers, a tool named in a comparison, a README in a code chat, and a deck-plus-workbook chat given the wrong chips. The detectors were then tightened (Jira keys need a ticket word or an Atlassian link; a person needs a person verb in front, not "for"; a tool needs a use word; a code chat ignores README and PDF; the latest output decides the chips). Two recall misses were accepted as the price of that (Jira keys with no ticket word, a client named after "for"). The `teach` row measures the card's gating only: how well the edit detector (C4) finds real, consistent edits is measured in its own tests. The labels were written before the detectors were tuned on them, but the fixtures are small and written by the same team, so read the numbers as a floor check, not a field measurement. Re-measure on real use before raising any type's budget.
