# 0.0.13 fixes for what 0.0.12 left open

Branch `claude/fix-0012-issues`, cut from 0.0.12 (origin/claude/happy-faraday-d7a4mi). Model: DeepSeek V4.1 Flash only (`MH_MODEL_ALLOW`), real runs through `python3 -m meshpool_harness -p "..." --auto --output-format stream-json --profile work` in scratch folders.

## 1. Cowork over-delivery

Nine vague or open-ended asks, 1 run each, same machine, 5 in parallel (so wall times are noisy). "Before" is the 0.0.12 code with the 0.0.12 skills, "after" is this branch (the installed skills were refreshed by the new hash rule; checked by hash).

| Ask | Before: tool calls / secs / files | After: tool calls / secs / files | Delivered after |
|---|---|---|---|
| Newsletter for a coffee shop | killed at about 13 min, 46+ calls (memory-tool loop, no file) | 13 / 100 s / 1 html | yes (one html page) |
| "plan a newsletter launch" | killed at about 13 min, 383 calls (memory_view loop, no file) | 9 / 60 s / 0 | yes, plan in the reply (the independent reviewer asked for a file once; see below) |
| Plan my week from tasks.txt | 8 / 46 s / md plus docx | 1 / 7 s / 0 | yes, table in the reply |
| Summarize the notes folder | 6 / 13 s / 0 | 6 / 13 s / 0 | yes |
| Reply to an email | 4 / 13 s / reply.txt | 2 / 7 s / 0 | yes, draft in the reply |
| Short report on AI in support | hung after 12 calls (search rate limited), killed | hung after 9 calls (same search errors), killed at about 10 min | no |
| Compare 3 note apps in a table | 21 / 94 s / 0 | 36 / 274 s / 1 md | yes (table), slower: web search retries |
| Agenda for a 1-day offsite | 187 / 426 s / docx, pdf, 3 png in the project | 11 / 141 s / 1 docx | yes |
| Social posts for an app launch | 16 / 157 s / 1 md | 22 / 103 s / 1 md | yes |

Totals for the six asks that finished in both: before 242 calls, after 78. The two worst before cases were loops, not skill over-delivery: the model wanted to ask questions, headless has no `ask_user`, so it called memory tools hundreds of times. The 90-call tracker-workbook run from 0.0.12 was not reproduced. Not every number improved (compare and social got slower or longer); one run each is directional only.

Changes:
- WORK_SYSTEM rule 0: do the asked thing first, one deliverable, no plan or tracker files, answer in the reply when it fits, research only as deep as needed, skills are guides, ask only when truly blocked.
- Skills rewritten or trimmed: email-newsletter, blog-post, daily-plan, briefing-interview (only on request, at most 4 questions), project-plan (small plan is a checklist, no workbook), competitor-analysis (one deliverable, 3 companies), research-brief, meeting-prep, seo-content-brief, feedback-synthesis, survey-analysis, interview-plan. Old unedited copies are refreshed by hash (`REFRESHED_DEFAULTS`); edited copies stay.
- `use_skill` result tells the model to size the work to the request, for every skill including user-installed ones.
- Research budget notes per turn (8 lookups: write now; 16 and up: stop; a fetch of a search engine page: use web_search). The 170-fetch run was paging a search engine.
- A call repeated more than 10 times in a turn is not run and the model is told to write the deliverable.
- The independent reviewer is told not to demand a file, tracker or extra format that was not asked for, and not to ask for invented facts.

## 2. Grader read-back
`agent/grader.py`: rubric READ-BACK RULE, evidence section "Actions the agent made in connected apps" (accepted writes, done once), code guard: a not_met item that names a live effect and says it cannot be read back becomes unverified; fix and blocker lines that tell the agent to redo a live write (re-send, "call create_booking again", probe or test bookings) are dropped; the rework message says never rerun a call that already succeeded. The guard only fires when the text names a live effect, so file defects ("did not see the chart in report.docx") and file fixes ("Recreate the chart") are untouched (tested). Tests: `tests/test_grader_readback.py` (reproduces the 0.0.12 case, plus an Agent-level gate test).

## 3. MCP soft-failure detector
Now only: JSON object with ok or success false, a non-empty `error` or `errors` key without data keys, a JSON-RPC error, an HTTP status of 400 to 599 (`status`, `status_code`, `statusCode`, `http_status`) without data keys, `status: "error"`; and plain text only when it is one line under 200 characters and starts with Error, Failed, Fatal and so on followed by a colon. Long text, logs, grep output, docs about errors and tracebacks are content. Behaviour changes to know: multi-line "Error: ..." messages and `{"status": "failed", ...}` job records are no longer marked failed (servers that really fail should set isError). `tests/test_mcp_soft_failure.py` has false-positive cases (log reader, grep, docs search).

## 4. Left-behind folders
`ui_audit` and `view_output` pictures now go to a temp folder (`<tmp>/meshpool-shots/<project hash>/<pid>/`), pruned after a day, and the tools print the path. Nothing is written to the project. `tests/test_shots_dir.py`. The 0.0.12 agenda run left `Meshpool outputs/views`; the after run left none.

## 5. ui_smoke
Touch drag: finds draggable things (draggable, grab cursor, handle classes), drags with a mouse, then with emulated touch events (press, hold, slide, lift) in a touch context; mouse works and touch does not is a SHOULD FIX. If the mouse drag does not move anything either it is a note, not a finding. Notification: the API is stubbed, the test "grants" it; output says "needs permission, button present" as a note, or a finding when the code uses Notification and nothing asks for permission, or shows alerts without asking. Heuristic: first draggable and first other column only; a board needing an exact drop spot reads as not verified; native HTML5 drag is not moved by emulated touch in Chromium, so it is reported with the caveat that phone support varies. Alert timing (a timer ending) is not tested. Tests in `tests/test_ui_smoke_touch.py`.

## 6. Real MCP shapes
`tests/test_mcp_real_shapes.py` starts a local streamable-HTTP server that answers in an SSE stream (empty priming event, keep-alive comments, a progress notification before the result), with `$ref`/`$defs`, `anyOf`, `oneOf` schemas and 300 tools with long descriptions. All passed without client changes. Also run with the real model: 302 tools through the lazy index, found `ship_order`, filled the nested `$ref` address and `anyOf` date correctly, call logged by the server. Change: long lists get shorter index lines (70, 45, 28 characters, names only past 400). OAuth cannot be tested locally against a real provider; only the existing local mock is covered.

## Still weak or unverified

- Before runs of two asks were killed after a loop, so "before" for them is a floor.
- The loop guard refuses repeats but cannot end a turn by itself.
- Small asks now often produce no file; a user who wanted a file must say so.
- Reviewer asked for a file for the launch plan once; the new scope rule was added after that run and was not re-measured.
- Touch drag and Notification checks were exercised on synthetic pages, not on real kanban or pomodoro builds.
- Full test suite not run (known LibreOffice failures); targeted files only.
- No desktop app run; OAuth servers untested.
