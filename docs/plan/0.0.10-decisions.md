# 0.0.10 decisions

Format: decision, then the reason in one line.

1. Memory store lives in a new `memstore.py`; `assistant.py` keeps every old signature and delegates. Reason: harnesses and the MCP server must not change.
2. `facts.jsonl` is rewritten atomically under the existing memory lock on every change. Reason: simple, safe with 1,000 facts, and the file stays human-readable.
3. Folder-linked project notes (no project id) use scope `project:folder-<key>`. Reason: the brief lists three scope forms; this keeps them inside the `project:` form.
4. The `memory.md` export holds active, everywhere-scope facts only. Reason: an older app reading it must never see pending or private-scope facts.
5. The agent saving through `memory_save` is `stated`, because the instructions only allow it when the user said it. Reason: stated beats inferred.
6. Conflicts are found with a small rule list (fonts, length, tone, always/never on the same words), no model call. Reason: detection uses zero model calls.
7. New JS goes in new files (`memory.js`, `insights.js`, `yourwork.js`) with thin hooks in `app.js`. Reason: keeps diffs reviewable.
8. Fast-model work (portrait, categories, summaries, phrasing) is cached on an input hash and skipped when `MH_LEARN=0` or no endpoint is reachable, with a rule-based fallback text. Reason: cheap, and tests stay offline.

## C3 summaries and Your work (fork wt-summaries)

9. Chat summaries are made by `summaries.on_idle(sid)` / `refresh_idle()` (the lead calls one at chat idle or app open), never during a turn. Reason: turns must not slow down.
10. Summaries, briefs and the Your work page skip any chat whose meta has `incognito: true`, and a chat that turns incognito loses its stored line. Reason: incognito reads and logs nothing for summaries.
11. Cost in USD and routing savings in USD are returned as null, with a note. The outcome log holds tokens only; savings need measured per-harness cost for the same spec, which the log does not carry. Reason: honest numbers, nothing invented.
12. Topics are keyword clusters over chat summaries and titles (no model). Spec names map to plain kinds of work (Slides, Code, Research). Reason: zero model calls.
13. The recap image takes only `recap_inputs()`: counts, kind names, agent names, busiest weekday and hour. No topics, titles, file names, connector names or memory text, and the PNG carries no metadata. Reason: shareable by design.
14. Suggestions on Your work use `insights.work_suggestions(months)` when it exists, else local rules (schedule: 3+ chats with near-identical first request; skill: 3+ similar, tool-heavy chats; project: 3+ loose chats on one topic). Each carries evidence and an action payload. Reason: concrete changes only, quiet when there is no pattern.
15. `touch_opened` is called by `catch_me_up` itself, so the catch-up uses the visit before the current one. Timestamps use millisecond precision so a chat saved just before a visit does not look new.
9. Visible checks are recorded in a small file under `checks/` (pointer file plus `MH_CHECK_RUN`), not in process memory. Reason: the office tools often run in another process than the app. Only rules that ran count; `not_run` rules are never listed.
10. Deck and workbook rules are recorded once per validation from the validators' own per-rule status (pass and warn count as passed, fail is counted apart). "Office schema" is listed only when schema validation really ran; otherwise the line says "Office file structure". Reason: never show a check that did not run.
11. The receipt shows a dollar cost only when the user has set `MH_PRICE_IN` and `MH_PRICE_OUT` (the terminal's existing variables); the repo has no price table. Otherwise it shows measured tokens and "cost not measured". `hrouter/outcomes.py` rows gain a `reason` field.
12. "Learn from my edits" is stored in `memory/learn-edits.json` (and honours `learn_from_edits: false` in `memory/settings.json`). Reason: `assistant.save_settings` rewrites `settings.json` with only its two keys and would erase a third.
13. A teach rule needs at least 3 changed places and at least 70% of the places it could apply to. An added sheet counts only when the same name is added in 2 different files. A file changed within 5 seconds of its registration is treated as Meshpool's own edit. Reason: one-off edits are noise.
14. Accepting a font rule updates the active company look only when it is a Meshpool-built look (not a master template); it never creates a profile.
9. Insights settings (switch, quiet hours, learn-from-edits) live in `insights/settings.json`, not the memory settings file. Reason: `assistant.save_settings` rewrites that file with only its two keys and would erase them.
10. Chats are read from `session.json` and `meta.json` into a small record; detectors take a `Corpus`, so tests and the precision script need no app. Reason: zero coupling to `agent_api` internals.
11. Chats count as the same request at 0.8 word overlap (numbers blanked), outside scheduled runs. Reason: 0.6 clustered one-off chats that only shared a template, which made noise cards.
12. A regular rhythm (gaps within 35% of the median, 18 hours to 45 days) makes a `schedule` card; the same repeated multi-step request without a rhythm makes a `skill` card. Reason: one pattern gets one card type.
13. `remember` cards add a pending fact only when accepted (`memstore.notice`), never straight to memory; a person must follow a person verb ("email Sara"), a tool a use word. Reason: precision on places, companies and comparisons.
14. Home budget counts showings per day in `state.json` (not live cards), so dismissing three cards does not buy three more the same day. Reason: "3 on the home screen per day".
15. Route "cheaper" compares tokens (in plus out) from the outcome log, not money, and needs equal or lower failure rate and 10+ turns of that spec. Reason: honest numbers; the log has no prices.
16. The `teach` detector reads candidates from `meshpool_harness.teach.detect()` when that module exists (C4), shape `{file, chat_id, kind, count, total, rules, label}`; otherwise none. Reason: C4 is built separately.
17. All nine types ship on: measured precision is 1.00 on the labelled situations after the tightening recorded in `0.0.10-precision.md`; recall misses were accepted for precision.
18. Imported facts (pasted answer, chat exports) land as pending `stated` facts with source `import` in the "Meshpool thinks" tray. Reason: inferred or bulk facts must not reach an agent before the user confirms.
19. The import screen is cut to three numbered actions with direct links to the ChatGPT and Claude export pages. Reason: fewest clicks and words to explain what happens; it is part of 0.0.10.
20. Bring-your-own Claude subscription inference is not built. Reason: forwarding consumer-plan OAuth tokens from a hosted service conflicts with Anthropic's terms for those tokens; offered import (E), API-key or cloud-provider access, or the local Claude Code harness instead.

## Added during the final pass (numbers above repeat because three branches were merged; read them by section)

- A suggestion is one quiet line above the composer (a yes button, a menu, a dismiss), never a card in the middle of the screen. Reason: suggestions must not be the star of the show.
- Home shows at most 2 cards a day, one per type, and none below a minimum ranked score (0.35). Reason: no card is better than a weak card; three cards of one kind is one idea.
- Copy was cut on every new screen: one idea per line, evidence behind "Why this?". Reason: people skip walls of text.
- Export-page links for the old assistants are served by `importer.EXPORT_LINKS`, not written in the JS. Reason: `test_ui_brand` keeps other vendors' names out of the interface files.
- Code sessions are grouped by folder by default (Date is one click away), with per-folder collapse, a new-session button, search and a waiting strip. Reason: the user asked for folders first and a smooth list.
- Piece E (import from other agents) lives in one module, `agent_import.py`, whose only file reader refuses anything that looks like a login (`.credentials.json`, `auth.json`, `.env`, `*token*`, `openclaw.json`). Reason: one place to audit; a test proves no login file is opened.
- Imported tools lose secret-looking env vars, headers, URL keys and arguments, and the report lists them by name. The older importer uses the same stripping. Reason: credential connection is a separate, explicit step.
- Imported memories are pending facts; instruction files are listed but not ticked by default. Reason: they change how every agent behaves, so they need a deliberate tick.
- `~/.claude.json` is opened only to read its `mcpServers` entries (that is where user-scope tools live); the credentials file next to it is never opened. Reason: tool definitions are the point of the import.
- Playwright is a core dependency (requirements, CLI requirements, pyproject) and browser use installs it on first use when it is missing, outside the packaged app. A Chromium any Playwright left on the computer is used before a download. Reason: UX and UI checks (`/qa`) need the browser tools, and they must not depend on a manual `install-browser` step.
