# 0.0.11: everything Meshpool needs is inside the app

Goal from the product owner: nothing the packaged app needs may require a download, an install step, or a program already on the customer's computer. This is the audit of what the packaged app (Mac Apple silicon, Mac Intel, Windows, Linux, from `packaging/build_all.py`) fetched or called at run time, what was done about each item, and how the macOS 11 promise is kept.

"Today" is the state of 0.0.10. Sizes are what the item adds to one installer (compressed download size; the unpacked size is in brackets where it matters).

## What changed

- `packaging/bundled_tools.py`: `WHEEL_PROGRAMS` (ffmpeg, pandoc: one pinned URL and SHA-256 per platform), `fetch_wheel_program`, `WHISPER_*` and `fetch_whisper_model`.
- `packaging/build_all.py`: `media_tools()` and `speech_model()` for all four platform trees (`<app>/vendor/ffmpeg`, `vendor/pandoc`, `vendor/whisper/base`).
- `packaging/requirements-cli.txt` (what the release installs), `requirements-runtime.txt` and `requirements-pinned.txt` (mirrors the update manifest hashes), `packaging/mac/constraints.txt` (pins for the native packages the Mac runner would otherwise resolve to newer builds).
- `app/meshpool_harness/bundled.py`: `bundled_ffmpeg()`, `bundled_pandoc()`, `whisper_model_dir()`, `ffmpeg_needs_newer_macos()`, `program_version()`, `speech_status()`; `use_bundled_tools()` puts ffmpeg and pandoc on PATH and sets `MESHPOOL_WHISPER_MODEL`, `HF_HUB_OFFLINE=1` and `MESHPOOL_PYTHON`.
- `app/meshpool_harness/config.py`: the system check (Settings, System, and `meshpool check`) lists ffmpeg, pandoc, Speech to text and Notebooks, with the versions that are really there.
- Skills: transcribe-audio (with `transcribe.py`), convert-files, pdf-tools, image-tools, notebooks, query-database, make-chart. `skills.REFRESHED_DEFAULTS` replaces an installed copy of these seven only when it is still byte for byte the 0.0.10 text, because an install otherwise keeps the default skills it was first given.
- `packaging/smoke.py`: after every build the release workflow now runs ffmpeg, pandoc, a transcription with the bundled model (offline), a notebook with the bundled kernel, a chart and HEIC registration from the built app.

## The macOS 11 floor

The last release build failed because new packages carried macOS binaries that need macOS 12 to 15 while the app promises 11. The wheel tag does not settle it (pypdfium2 5.x, the pandoc wheels and onnxruntime say 11 and need 12 to 15), so the load commands inside the files are read:

- `packaging/mac/wheel_minos.py` (stdlib plus pip, runs on Linux): `closure` downloads the macOS wheels of a requirements file, dependencies included, for both architectures with pip's `--platform` and the bundled Python 3.12, and reads `LC_BUILD_VERSION` and `LC_VERSION_MIN_MACOSX` of every Mach-O file in each (this architecture's slice of universal files; it reuses the parser of `check_minos.py`). `programs` does the same for the ffmpeg and pandoc wheels and also reads the libraries each program loads (all of them are `/usr/lib` or `/System/Library`). `--record` writes `packaging/mac/verified_minos.json`.
- `app/tests/test_macos_floor.py` (offline) holds the repository to that record: every package in `requirements-cli.txt` was read, every `==` pin is the version that was read, nothing recorded needs more than 11.0 except the named exemption (playwright's own Node, which the build replaces), the packages whose newer builds are known to break (onnxruntime, debugpy, protobuf) stay pinned, no opencv or rapidocr slips into the requirements, and the ffmpeg and pandoc pins are the wheels that were read. Adding a package without reading it, or moving a pin, fails the test.
- `.github/workflows/tests.yml` re-reads the live wheels on every run of the tests, so a wheel that changes upstream is caught too.
- `.github/workflows/release.yml`: one new exemption, `vendor/ffmpeg/*=12.0`, because the Apple silicon ffmpeg needs macOS 12 (read from the file; imageio-ffmpeg 12.0, martin-riedl.de 12.0, osxexperts 13.0: none runs on 11). `bundled.ffmpeg_needs_newer_macos()` says so on such a Mac, keeps ffmpeg off PATH there, and Settings shows the row as "needs macOS 12 or later". Speech to text does not use the ffmpeg program (PyAV decodes), so it works on macOS 11; so do PDF, image, document and spreadsheet tools. Intel Macs run the macOS 11.0 build. A follow-up that removes the exemption is building FFmpeg from source with `MACOSX_DEPLOYMENT_TARGET=11.0` in the style of `packaging/mac/build_git.sh`.

Versions that were read and rejected, so nobody tries them again: onnxruntime 1.20+, debugpy 1.8.9+, protobuf 7.x, opencv-python-headless 4.9.0.80 (Intel: 12) and 4.10+ (Intel: 12 to 13), imageio-ffmpeg 0.6 and 0.7 on Apple silicon (12), pypandoc_binary 1.14 to 1.17 (12 to 15), official pandoc 3.1.13 (Apple silicon 14), 3.6.4 (13 to 15), 3.8.3 (15 to 26).

## What only the release workflow can verify

Nothing here was built or run on a Mac or on Windows. Verified on Linux: the pinned downloads (hashes and sizes), the extraction code, the Linux ffmpeg, pandoc and speech model running, a real English recording transcribed offline with the bundled model (through PyAV and also through the bundled ffmpeg), notebooks run with the pinned kernel packages, the macOS floor of every Mac wheel and program (read, not assumed), and all the new tests. To be checked by the release builds:

- that the pins resolve together with Hermes' requirements (`hermes-req.txt` is generated in the workflow; a conflicting pin fails the "Third-party runtimes" step, which is where to look first);
- `old_macos_wheels.py` and `check_minos.py` over the finished Mac apps (they also read what pywebview's macOS-only packages bring, which the Linux closure cannot resolve);
- ffmpeg, pandoc, CTranslate2 and PyAV actually starting on macOS and Windows (the new step in `packaging/smoke.py` does this); on Windows the Visual C++ runtime that CTranslate2 and ONNX Runtime need comes with the bundled Python, which is unconfirmed;
- ad hoc and Developer ID signing of the new binaries (`sign.sh` signs every Mach-O it finds);
- the size of the disk images against the runner's free space (about 260 MB more per installer).
